Design Thinking & Figma • CLO2 View Figma Prototype ↗

Interactive Data-Driven Mobile Prototype

Applied the 5-stage Design Thinking process (Empathize, Define, Ideate, Prototype, Test) to design an interactive Figma wireframe translating user pain points into structured data inputs.

1. What I Learned

Good data engineering begins at the user interface—clean input validation and clear user flows prevent messy downstream records.

2. Challenge / Decision

Our initial wireframe cluttered the dashboard with too many metrics. We prioritized three core user indicators after peer usability feedback.

3. Connection to Course / CLO

Connects Data Acquisition and Design Thinking to how upstream applications generate structured data.

4. What I Would Improve

Add explicit error-state screens and field validation rules in Figma to show how invalid inputs are caught before ingestion.

Other Selected Evidence • Data Acquisition & Analytics View Notebook & Dashboard ↗

Transaction Dataset Cleaning (Colab) & Looker Studio Dashboard

Cleaned and aggregated multi-attribute CSV transaction records using Python (pandas) in Google Colab, then built an interactive multi-page Looker Studio report analyzing payment volumes, routing patterns, and hourly traffic.

1. What I Learned

Standardizing timestamps, null categories, and data types in pandas before exporting prevents misleading spikes in visual dashboards.

2. Challenge / Decision

High-cardinality fields made initial charts unreadable; I grouped edge categories and structured separate pages for volume vs. hourly trends.

3. Connection to Course / CLO

Applies Data Acquisition, Transformation & Serving end-to-end using industry-relevant analytics tools.

4. What I Would Improve

Automate data quality assertions (schema checks and row-count logs) in Python so repeatable runs validate inputs automatically.
